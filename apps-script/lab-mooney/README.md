# ซิงก์ Google Sheets → Supabase สำหรับ MNP LAB

Google Sheets **Mooney_Test_Report** เป็นแหล่งข้อมูลหลักสำหรับกรอก/แก้ไข หน้าเว็บอ่านข้อมูลสำเนาที่ผ่านการซิงก์จาก Supabase
จึงไม่ต้องรอ Apps Script อ่านชีตขณะเปิดหน้า การซิงก์ตั้งรอบทุก 1 นาที และเว็บอ่านฐานข้อมูลใหม่ทุก 30 วินาทีเมื่อเปิดแท็บ
เวลาจริงขึ้นกับ Google/เครือข่าย หน้าแสดง **วันเวลาอ่านชีต** และสถานะเมื่อข้อมูลเก่ากว่า 3 นาที ไม่แสดงว่าเป็นข้อมูลสดเมื่อซิงก์ไม่ได้

```
Google Sheets → Apps Script Sync.gs (ทุกนาที + script lock)
              → Edge Function lab-sheet-sync (ตรวจ integration secret)
              → app_lab_mooney_publish (service_role เท่านั้น, ธุรกรรมเดียว)
              → ตารางผล + ลำดับในชีต + สรุป + เวลาอ่านล่าสุด
เบราว์เซอร์   → app_lab_mooney_feed (ตรวจสิทธิ์ LAB ทุกครั้ง)
              → หน้ารวม: สรุปเท่านั้น / หน้าวัสดุ: แถวของวัสดุที่เลือกเท่านั้น
```

## ลำดับเปิดใช้งาน (ฐานข้อมูลก่อนเว็บ)

1. ให้ CI ของ PR ผ่าน รวม database tests และขออนุมัติผู้ใช้เพื่อ apply migration **นี้** บน production
   ยืนยัน project `iqlydmkylqyowmvpsete` (`MNP_SYSTEM`) และตรวจว่าฟังก์ชัน import ยังไม่มี หรือเป็น definition เดิมจาก main
   เมื่อสำรวจ 16 ต.ค. 2026 ตารางมี 0 แถวและ production ไม่มี `app_lab_mooney_import`; migration ใหม่จึงรวม definition จาก main ไว้แล้ว
   ห้ามรัน migration เก่าทั้งไฟล์ซ้ำ ห้าม reset ฐานข้อมูลจริง
2. Apply ไฟล์ `supabase/migrations/20261016044946_lab_supabase_read_model.sql` จาก commit ที่ตรวจแล้ว
   ไม่มีการแก้ `private.can_access_lab()` หรือกติกาสิทธิ์เดิม ตรวจ grants/schema/function hashes หลัง apply
3. สร้าง secret แบบสุ่มอย่างน้อย 32 bytes (เช่น hex 64 ตัว) ใน secret manager ห้ามส่งค่ามาในแชตหรือ commit
   ตั้ง `LAB_SHEET_SYNC_SECRET` ใน Edge Function และ Script Properties ของโปรเจกต์ Apps Script ให้ตรงกัน
   Edge Function ใช้ `SUPABASE_SERVICE_ROLE_KEY` ที่ระบบเตรียมไว้ ไม่ใส่ service key ใน Apps Script
4. Deploy โฟลเดอร์ `supabase/functions/lab-sheet-sync/` **พร้อม import ของ `modules/lab-mooney-model.js`**
   ใช้ CLI จาก root checkout เพื่อให้ bundler resolve ไฟล์ร่วมได้ `supabase/config.toml` กำหนด `verify_jwt = false`
   เพราะใช้ secret ของ integration แทน user JWT ตัว handler ปฏิเสธทุกคำขอก่อนอ่าน body เมื่อ secret ไม่ตรง
   เก็บ secret เฉพาะการเชื่อมต่อนี้และจำกัดผู้แก้ไข Apps Script ห้ามเปิด endpoint ที่ยังไม่ตั้ง secret ให้ใช้งาน
5. ในโปรเจกต์ Apps Script เดิม เพิ่มไฟล์ **Sync.gs** จากโฟลเดอร์นี้ คง **Code.gs** เดิมสำหรับ parser และ rollback
   ตั้ง `SHEET_ID` หากเป็น standalone script และเขตเวลา Bangkok เช่นเดิม ไม่ต้อง deploy Web App รุ่นใหม่เพื่อเรียก time trigger
6. รัน `installLabSync` ด้วยบัญชีเจ้าของที่อ่านชีตได้ และอนุญาต Google scopes ที่เกี่ยวข้องกับ Sheets/URL Fetch/triggers
   ฟังก์ชันจะซิงก์ครั้งแรกให้สำเร็จก่อนติดตั้ง trigger; รันซ้ำไม่เพิ่ม trigger ซ้ำสำหรับบัญชีเดียวกัน
   ใช้บัญชีเจ้าของหนึ่งบัญชีติดตั้งเท่านั้น (Google ไม่ให้ลบ trigger ของบัญชีอื่น)
7. ตรวจ Script Properties `LAB_SYNC_LAST_SUCCESS` และไม่มี `LAB_SYNC_LAST_ERROR` ตรวจว่าจำนวนแถว/วัสดุตรงชีต
   ทดสอบ RPC ด้วย session admin จริงและ staff จริง: admin อ่านได้, staff ถูกปฏิเสธ และ anon ไม่มีสิทธิ์ execute
   เทียบลำดับแถว ค่า AVG/SD ที่ merge ตัวอย่างอย่างน้อยหนึ่งวัสดุ และเวลาข้อมูลก่อนเปิดเว็บรุ่นใหม่
8. **Merge PR/เผยแพร่ Pilot assets เป็นขั้นตอนสุดท้ายเท่านั้น** เว็บใหม่ไม่ fallback อ่านชีต หากยังไม่ซิงก์จะแสดง `LAB_SYNC_NOT_READY`

## ความถูกต้องและกรณีผิดพลาด

- เก็บลำดับแถวจากฟีด ไม่เรียงใหม่ตาม timestamp เพื่อให้การจัดชุด/กราฟ/AVG/SD ตรงหน้าเดิม
- สรุปคำนวณด้วย `modules/lab-mooney-model.js` ชุดเดียวกับหน้าเว็บครั้งเดียวต่อรอบ ไม่ทำสำเนาสูตรใน Apps Script/SQL
- หน้าเลือกวัสดุรับทุกแถวของวัสดุนั้น (ภายในขีดจำกัด snapshot 20,000 แถว) ไม่มีการตัดเงียบที่ 2,000 แถว
- ถ้าชีตว่าง/มีแถวอ่านไม่ได้/เกิน 20,000 แถว จะไม่ส่ง snapshot และคงข้อมูลครั้งล่าสุด แก้ชีตแล้วรอรอบถัดไป
  แถวเดียวที่ไม่สมบูรณ์ (เช่น ยังไม่กรอก MH/MV, ปี พ.ศ., ช่องตัวเลขเป็นข้อความ) ทำให้ **ทั้งชุดค้าง** ตามที่ออกแบบไว้
  เมื่อ `LAB_SYNC_LAST_ERROR` เป็น `LAB_SYNC_INVALID_SNAPSHOT` ให้เปิด Script Property **`LAB_SYNC_LAST_PROBLEMS`**
  จะบอกแท็บ เลขแถว และเหตุผล (ไม่เกิน 20 แถว) ไม่มีค่า secret และไม่เขียนลง execution log; แก้ชีตแล้วค่านี้ถูกลบเองเมื่อซิงก์รอบถัดไปผ่าน
- import ทำการเพิ่ม แก้ไข และลบแถวที่หายไปใน transaction เดียว พร้อม audit และด่านกันลบเกินครึ่งตาม importer เดิม
  ไม่รับ force-delete จาก HTTP หากพบ `SYNC_REJECTED` ให้ผู้ดูแลตรวจชีตและจำนวนที่จะลบก่อนดำเนินการด้วยสิทธิ์ server
- จับเวลา **ก่อน** อ่านชีต และปฏิเสธ snapshot ที่เก่ากว่ารอบที่เผยแพร่แล้ว แม้คำขอจะมาถึงสลับกัน
- รอบที่ข้อมูลไม่เปลี่ยนอัปเดตเวลาความสด แต่ไม่เขียนผลทดสอบ/audit ซ้ำทั้งชุด
- ปุ่มรีเฟรชหน้าเว็บอ่าน **ฐานข้อมูล**; ถ้าต้องการอ่านชีตทันทีให้เจ้าของรัน `syncLabMooney` ใน editor
- ตัวซิงก์ไม่ log ข้อมูลชีต/token/response ภายใน และเก็บ error code กลางใน `LAB_SYNC_LAST_ERROR`
- หากแก้โค้ดสรุปใน model ภายหลัง ให้ redeploy worker จาก commit เดียวกับเว็บก่อนรอบซิงก์ถัดไป

## ตรวจผลความเร็วและ rollback

วัดด้วยอุปกรณ์/เครือข่ายเดียวกัน: เปิด LAB ครั้งแรก, เปิดวัสดุ, กลับหน้ารวม, สลับวัสดุที่เคยเปิด และกด refresh
ตรวจ Network ว่าหน้ารวมไม่มี raw rows และไม่มีคำขอไป `script.google.com`; หน้าวัสดุต้องระบุ `p_material`
แยกเวลา RPC, JS/render และเวลาจนเห็นผล ไม่ใช้เวลา unit test เป็นเวลาโหลดจริง และไม่รับประกัน 8 ms

หากต้องย้อนกลับ ให้ revert **Pilot assets ทั้งชุดและ cache version** ไป commit ก่อน PR นี้ (อ่าน Web App เดิม)
แล้วให้เจ้าของรัน `removeLabSyncTrigger` หากต้องการหยุดซิงก์ เก็บตาราง/metadata/ฟังก์ชันใหม่ไว้เพื่อกู้คืนได้
ไม่ลบ source sheet หรือข้อมูลสำเนาระหว่าง rollback และไม่แตะ workflow โมดูลอื่น

## เอกสารฟีดเดิมสำหรับ rollback เท่านั้น

ขั้นตอนด้านล่างอธิบาย Web App เดิม (`Code.gs → doPost`) ที่ยังคงไว้รองรับเว็บรุ่นก่อน:

Google Apps Script (Web App) สำหรับสเปรดชีต **Mooney_Test_Report** — ชีตเป็นข้อมูลต้นทางและ **ไม่มีสำเนาที่ไหน**
ทุกครั้งที่หน้า MNP LAB ใน Pilot Web เปิดหรือรีเฟรช (อัตโนมัติทุก 30 วินาทีขณะแท็บเปิดอยู่) เว็บเรียก Web App นี้
สคริปต์อ่านชีต ณ ตอนนั้นแล้วตอบกลับเป็น JSON (ลิงก์ชีตไม่ใส่ใน repo)

```
เบราว์เซอร์ (admin) ──POST {token}──▶ Web App (Code.gs) ──app_lab_access + โทเค็นของผู้ใช้──▶ Supabase
                                          │                                                     │ true = admin / false = ไม่ใช่
                                          │◀────────────────────────────────────────────────────┘
                                          └─ true เท่านั้น: อ่านชีต → ตอบ JSON      อย่างอื่น: ตอบ error ไม่มีข้อมูล
```

## สิทธิ์ (ปฏิเสธไว้ก่อนเสมอ)

- เว็บแนบ **access token ของผู้ใช้ที่ล็อกอิน** ใน body สคริปต์ส่งต่อให้ Supabase ถาม `app_lab_access`
  (ฐานข้อมูลตัดสินที่ `private.can_access_lab()` — ตอนนี้ admin เท่านั้น ภายหลังเพิ่มรายชื่อ ID ที่ฐานข้อมูลจุดเดียว สคริปต์ไม่ต้องแก้)
- คืนข้อมูลเฉพาะเมื่อ Supabase ตอบ HTTP 200 และเนื้อหาเป็น `true` พอดี ทุกกรณีอื่นไม่มีข้อมูลหลุด:
  ไม่มีโทเค็น/รูปแบบไม่ใช่ JWT, โทเค็นผิดหรือหมดอายุ, ตอบ `false`, Supabase ล่ม, อ่านผลไม่ได้
- เปิด URL ของ Web App ในเบราว์เซอร์ (GET) ได้แค่ `{"ok":false,"error":"USE_POST"}`
- สคริปต์ **ไม่มี secret**: URL และ publishable key ของ Supabase ในโค้ดเป็นค่าสาธารณะ (อยู่ใน `app.js` ของเว็บอยู่แล้ว)
  และไม่บันทึกโทเค็นลง log หรือ cache
- ข้อควรรู้: โทเค็น (อายุสั้น ราว 1 ชั่วโมง) ถูกส่งไปยัง Apps Script ของบัญชี Google ขององค์กรเอง ใครแก้ไขสคริปต์นี้ได้
  ย่อมเปลี่ยนโค้ดให้เก็บโทเค็นได้ จึงควรจำกัดผู้มีสิทธิ์แก้ไขโปรเจกต์ Apps Script เฉพาะผู้ดูแลระบบ
- สคริปต์อ่านชีตด้วยสิทธิ์ของ **เจ้าของสคริปต์** ผู้ใช้เว็บไม่ต้องมีสิทธิ์เปิดชีต จึงตั้งแชร์ชีตเฉพาะคนที่ต้องแก้ไขได้
  (ไม่ต้องเปิด "ทุกคนที่มีลิงก์") ซึ่งปลอดภัยกว่า

## สิ่งที่สคริปต์ทำกับชีต

- อ่าน **ทุกแท็บที่มองเห็น** ที่แถวแรกคอลัมน์ A–H เป็น `ID, Material, TestDate, Time, Temperature, Test time, MH, MV`
  (แท็บอื่นถูกข้ามและแจ้งชื่อ)
- วันที่อ่านแบบ **วัน/เดือน/ค.ศ.** (`09/10/2026` = 9 ตุลาคม 2026) ตามที่ชีตแสดง
- คอลัมน์ `AVG MH, SD MH, AVG MV, SD MV` เป็นเซลล์ที่ merge หลายแถว สคริปต์ขยายค่าไปทุกแถวในกลุ่ม
  จึงตรงกับชีตทุกประการ ไม่คำนวณใหม่ (แท็บ `E00030S T` ไม่มีค่าเหล่านี้ จะแสดงเป็น —)
- **คอลัมน์ Lot (ไม่บังคับ)**: ใส่หัวคอลัมน์ `Lot` ที่คอลัมน์ **M** (ต่อจาก `SD MV`) ของแท็บ Mooney แล้วกรอกเลข Lot ของคอมพาวด์ต่อแถว
  หัวที่รับคือ `Lot`, `Lot No`, `Lot Number`, `ล็อต` (ไม่สนตัวพิมพ์/ช่องว่าง) ค่านี้ตัดช่องว่างหัวท้ายแล้วส่งเป็น `lot_number`
  ช่องว่าง = ไม่มี Lot ยาวได้ไม่เกิน **60 ตัวอักษร** — ยาวกว่านั้นแถวนั้นถูกปฏิเสธเหมือนแถวที่ข้อมูลไม่ถูกต้อง (`Lot ยาวเกิน 60 ตัวอักษร`)
  เพราะฐานข้อมูลจำกัด 1–60 ตัวอักษร และถ้าส่งไปจะทำให้การนำเข้าทั้งรอบล้มเหลว ถ้าไม่มีหัว Lot ที่ M สคริปต์ไม่อ่านคอลัมน์ M
  merge เซลล์ Lot ต่อชุดได้เหมือน AVG/SD (ทุกแถวในช่วง merge ได้ Lot เดียวกัน)
  และส่ง `lot_number` เป็น null (ทำงานเหมือนเดิม) ค่านี้ลงที่ `lab_mooney_results.lot_number` และเป็นค่าที่รายงานตรวจสอบคุณภาพ (QC inspection report)
  ใช้เชื่อมกับ `compound_lots` ไม่ต้องแก้ Edge Function `lab-sheet-sync` หรือฐานข้อมูลเพิ่ม นอกจาก migration `20261027010000_qc_inspection_reports.sql`
  (ต้อง apply ก่อน จึงจะมีคอลัมน์ `lot_number`) และต้องวาง `Code.gs` ใหม่ทับในโปรเจกต์ Apps Script
- แถวที่ข้อมูลไม่ถูกต้อง (เช่น วันที่ไม่ใช่ dd/mm/ค.ศ.) **ไม่แสดงในหน้าเว็บ** และกล่องเตือนสีเหลืองบอกแท็บ/เลขแถวให้ไปแก้ในชีต
  แถวที่เหลือแสดงตามปกติ

## ติดตั้ง / อัปเดต

1. เปิดโปรเจกต์ Apps Script ที่ deploy Web App ไว้ (ถ้าผูกกับชีต: ชีต > **Extensions > Apps Script**) วางเนื้อหา `Code.gs`
   ในโฟลเดอร์นี้ **ทับทั้งไฟล์** แล้ว Save
   - ถ้าโปรเจกต์ **ไม่ได้ผูกกับชีต** (สร้างจาก script.google.com ตรงๆ) ให้ตั้ง **Project Settings > Script properties**
     `SHEET_ID` = รหัสสเปรดชีต (ข้อความระหว่าง `/d/` กับ `/edit` ใน URL ของชีต)
2. **Project Settings** > Time zone ตั้งเป็น `(GMT+07:00) Bangkok`
3. **Deploy > Manage deployments** > ไอคอนดินสอที่ deployment เดิม > **Version: New version** > **Deploy**
   (ใช้ deployment เดิมเพื่อให้ URL เดิมที่อยู่ใน `modules/module-lab.js` ยังใช้ได้) ตั้งค่า:
   - **Execute as: Me**
   - **Who has access: Anyone** — จำเป็น เพราะเบราว์เซอร์เรียกแบบไม่มีบัญชี Google สิทธิ์จริงตรวจที่ฐานข้อมูลตามข้างบน
     (ถ้าเลือก "Anyone with Google account" เว็บอ่านคำตอบไม่ได้)
4. ครั้งแรกที่ deploy Google จะขออนุญาตสิทธิ์ (อ่านสเปรดชีต + ส่งคำขอไปภายนอก) ให้อนุญาต
5. ทดสอบ: เปิด URL ของ Web App (`.../exec`) ในเบราว์เซอร์ ต้องเห็น `{"ok":false,"error":"USE_POST"}`
   แล้วล็อกอิน Pilot Web ด้วยบัญชี admin > เมนู **MNP LAB**

> **อย่าเชื่อผลการกด Run `doPost` ในตัวแก้ไข Apps Script** เพราะตอนนั้นไม่มี `e` จริง ต้องทดสอบผ่านหน้าเว็บจริง

## ถ้าหน้าเว็บขึ้นข้อความผิดพลาด

| ข้อความในหน้าเว็บ | สาเหตุที่พบบ่อย |
|---|---|
| เชื่อมต่อชีตไม่ได้ … | ไม่มีอินเทอร์เน็ต, Web App ยังไม่ได้ deploy, หรือ "Who has access" ไม่ใช่ Anyone |
| อ่านคำตอบจากชีตไม่ได้ … โค้ดเวอร์ชันเก่า | Web App ยังเป็นโค้ดเก่า (ไม่มี `doPost`) ให้ deploy **New version** |
| ตรวจสิทธิ์กับระบบไม่ได้ชั่วคราว | Supabase ไม่ตอบ ลองใหม่ |
| อ่านข้อมูลจากชีตไม่สำเร็จ | สคริปต์อ่านชีตพลาด (ตรวจ `SHEET_ID` / สิทธิ์ของเจ้าของสคริปต์ต่อชีต) ดู **Executions** ใน Apps Script |
| หน้า "ไม่พบหน้าที่ต้องการ" | บัญชีนี้ไม่มีสิทธิ์ MNP LAB (ตามออกแบบ) |

## โควตา

Apps Script จำกัดจำนวนการเรียกต่อวันและจำนวนการทำงานพร้อมกัน (30) การใช้งานแบบ admin ไม่กี่คนและรีเฟรชทุก 30 วินาที
ขณะแท็บเปิดอยู่ (แท็บที่ซ่อนไม่ยิง) อยู่ในเกณฑ์ แต่ถ้ามีผู้ได้รับสิทธิ์จำนวนมากภายหลัง ควรทบทวนรอบรีเฟรช
(`REFRESH_MS` ใน `modules/module-lab.js`)

## ทดสอบโค้ด

ฟังก์ชันแปลงข้อมูลและ `doPost` (ทั้งกรณีได้รับอนุญาตและปฏิเสธทุกแบบ) ทดสอบด้วย stub ของบริการ Google:

```bash
node --test scripts/tests/lab-mooney-feed.test.mjs
```

ส่วนที่ต้องทดสอบบน Google จริง: `getMergedRanges`, การ deploy Web App, และการอ่านคำตอบข้ามโดเมนจากเบราว์เซอร์
