# สคริปต์ของสเปรดชีตระบบแจ้งซ่อม MNP (ซิงก์ใบแจ้งซ่อม + เติมฟอร์ม MT01-FM05)

ชุดโค้ดเขียนใหม่สำหรับโปรเจกต์ Apps Script **ที่ผูกกับสเปรดชีต "ระบบแจ้งซ่อม MNP System"** (Extensions > Apps Script)
ใช้แทนโค้ดเดิมที่ถูกวางทับเมื่อ 27/10/2569 มี 2 ไฟล์ในโปรเจกต์เดียวกัน:

| ไฟล์ใน repo | วางที่ไหนใน Apps Script | หน้าที่ |
|---|---|---|
| `Code.gs` | ไฟล์ `Code.gs` (วางทับทั้งไฟล์) | Web App รับการซิงก์จาก Pilot Web → ชีต "KV" และ "ใบแจ้งซ่อม" |
| `FormFill.gs` | ไฟล์ใหม่ชื่อ `FormFill` (กด + > Script) | พิมพ์เลขที่เอกสารที่ AG4 ของชีต "เอกสาร" แล้วฟอร์มเติมเอง + เมนู "ใบแจ้งซ่อม" |

ไฟล์ใน repo เป็นต้นฉบับ Apps Script ไม่ได้อ่านจาก repo แก้ที่นี่แล้วต้องไปวางเองทุกครั้ง

> ⚠️ **ห้ามวาง `apps-script/mt-form-export/Code.gs` ในโปรเจกต์นี้** — นั่นคือ Web App ดาวน์โหลด Excel ที่เป็นโปรเจกต์แยก
> วางทับแล้วการซิงก์และการเติมฟอร์มจะหายทันที (เหตุการณ์เมื่อ 27/10/2569)
> ห้ามวางไฟล์ฝั่งเว็บ (`modules/*.js`, `app.js`) ใน Apps Script ด้วย

## ติดตั้ง / กู้คืน

1. เปิดสเปรดชีต > **Extensions > Apps Script**
2. ดูรายการไฟล์ทางซ้าย ถ้ามีไฟล์อื่นนอกจาก `Code.gs` ให้คัดลอกเนื้อหาเก็บไว้ (เช่นวางใน Google Doc) ก่อน แล้วลบไฟล์ที่มี
   `function doPost`, `function doGet`, `function onEdit` หรือ `function onOpen` (ถ้าชื่อซ้ำกัน Apps Script ไม่เตือน
   แต่ใช้ตัวที่โหลดทีหลังแบบเงียบๆ ฟอร์มหรือการซิงก์จะทำงานผิดโดยไม่รู้ตัว)
3. เมนูซ้าย **Triggers** (ไอคอนนาฬิกาปลุก): ลบ trigger เก่าที่เรียกฟังก์ชันที่ไม่มีแล้ว หรือที่เรียก `onEdit`
   (ชุดนี้ใช้ simple trigger `onEdit` อยู่แล้ว ถ้ามี trigger ซ้ำ ฟอร์มจะเติม 2 รอบ)
4. เปิด `Code.gs` > เลือกทั้งหมด > ลบ > วางเนื้อหา `Code.gs` ในโฟลเดอร์นี้ > **Save**
5. กด **+ > Script** ตั้งชื่อ `FormFill` > วางเนื้อหา `FormFill.gs` > **Save**
6. **Deploy > Manage deployments** > ไอคอนดินสอที่ deployment เดิม > **Version: New version** > **Deploy**
   (ใช้ deployment เดิมให้ URL ใน `modules/module-mt.js` เหมือนเดิม ไม่ต้องแก้เว็บ)
   - Execute as: **Me**, Who has access: **Anyone**
7. อนุญาตสิทธิ์ที่ Google ขอ (ถ้ามี)
8. ทดสอบ:
   - เปิด URL ของ Web App ในเบราว์เซอร์ ต้องเห็น `OK`
   - เปิดใบแจ้งซ่อมใบหนึ่งใน Pilot Web (การเปิดหน้ารายละเอียดจะซิงก์) > กลับมาที่ชีต "ใบแจ้งซ่อม" ต้องมีแถวของใบนั้น
   - รีเฟรชสเปรดชีต ต้องมีเมนู **ใบแจ้งซ่อม** > พิมพ์เลขที่ใบนั้นที่ AG4 ของชีต "เอกสาร" ฟอร์มต้องเติมเอง
   - ลบค่าใน AG4 ฟอร์มต้องกลับเป็นแบบเปล่า

> อย่าเชื่อผลการกด Run `doPost`/`onEdit` ในตัวแก้ไข เพราะไม่มี `e` จริง ต้องทดสอบผ่านเว็บและชีตจริง

## การใช้งานบนชีต

- พิมพ์เลขที่เอกสารที่ **AG4** ของชีต "เอกสาร" (ตัวพิมพ์เล็ก/ใหญ่ได้) แล้วกด Enter → ฟอร์มเติมครบทุกช่อง แล้วพิมพ์ด้วย File > Print
- เมนู **ใบแจ้งซ่อม > ดึงข้อมูลใหม่** เติมซ้ำหลังข้อมูลอัปเดต, **ล้างฟอร์ม** คืนแบบฟอร์มเปล่า
- ค่าที่เติมมาจาก `formCells` ที่ Pilot Web คำนวณ (ชุดเดียวกับปุ่ม "ดาวน์โหลด Excel") จึงตรงกับไฟล์ที่ดาวน์โหลดทุกช่อง
- ขึ้นข้อความ "ยังไม่มีข้อมูลฟอร์ม" หรือ "ไม่พบเลขที่เอกสาร" = ใบนั้นยังไม่ได้ซิงก์หลังติดตั้งชุดนี้
  ให้เปิดใบนั้นใน Pilot Web หนึ่งครั้ง แล้วกด **ดึงข้อมูลใหม่**
- ชีตเก็บข้อมูลตามที่ **ผู้เปิดใบคนล่าสุดเห็น** ถ้าผู้เปิดล่าสุดเห็นข้อมูลไม่ครบตามสิทธิ์ (เช่นชื่อผู้อนุมัติ) ช่องนั้นอาจว่าง
  จนกว่าจะมีผู้ที่เห็นครบเปิดใบอีกครั้ง ข้อมูลจริงอยู่ในระบบเสมอ
- คอลัมน์ "จำนวนรูปภาพ" ของแถวเก่าที่มีลิงก์ดูรูป จะกลายเป็น 0 เมื่อใบนั้นถูกซิงก์ใหม่ (ระบบใหม่เก็บรูปใน Supabase ไม่ผูกลิงก์ในชีต)
- Web App รับเฉพาะ key `order:<uuid>` ที่ id ใน JSON ตรงกับ key คนที่ได้ URL ไปเขียนทับ key อื่นของระบบเดิมใน KV ไม่ได้
- การซิงก์เกิดเมื่อมีคนเปิดหน้ารายละเอียดใบ ใบที่เปลี่ยนระหว่างที่การซิงก์หยุด (27/10/2569) จะอัปเดตเมื่อมีคนเปิดใบนั้น

## สิ่งที่ชุดนี้ไม่ได้ทำ (ของโค้ดเดิมที่ไม่มีต้นฉบับ)

ชีต "KV" ยังมี key ของระบบเดิม (`config`, `orders`, `notifications`, `lineWebhooks`, `lineUsers`, `accessRequests`, `photos:*` ฯลฯ)
และคอลัมน์ "จำนวนรูปภาพ" ของแถวเก่ามีลิงก์ดูรูปไปอีก Web App หนึ่ง ชุดนี้ **ไม่ได้** สร้างส่วนเหล่านั้นใหม่
(LINE webhook ซึ่งเลิกใช้แล้ว, หน้าดูรูป, คำขอสิทธิ์) ข้อมูลเดิมในชีตไม่ถูกลบ ถ้ายังต้องใช้ส่วนใดต้องเขียนใหม่แยกเป็นงานต่างหาก
