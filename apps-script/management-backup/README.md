# สำรองข้อมูลใบคำร้องถึงฝ่ายบริหาร (PP01-FM08)

Google Apps Script สำหรับสำรองข้อมูลคำร้องประเภท `MANAGEMENT` (โมดูล "ใบคำร้องถึงฝ่ายบริหาร")
ไปเก็บไว้ในสเปรดชีต [ใบคำร้องถึงฝ่ายบริหาร](https://docs.google.com/spreadsheets/d/1LFsJZmsPOVAYPi3TFMkLDgRvkk4nV7ThZluNGnLWD_4/edit)
เป็นแค่สำเนาสำรอง/รายงาน — **Supabase ยังเป็นฐานข้อมูลหลักและเป็นตัวบังคับสิทธิ์/สายอนุมัติทั้งหมด**
ใช้รูปแบบเดียวกับสคริปต์สำรองใบแจ้งซ่อม (Maintenance-MT) ที่ Pilot Web (`app.js`) เรียกอยู่แล้ว

โฟลเดอร์นี้มี 2 ไฟล์ในโปรเจกต์ Apps Script เดียวกัน (ผูกกับสเปรดชีตเดียวกัน):

- `Code.gs` — รับข้อมูลจาก Pilot Web (`doPost`) แล้วบันทึกลงชีต
- `FormFill.gs` — เติมฟอร์มพิมพ์ในชีต "เอกสาร" จากเลขที่เอกสาร (ดูหัวข้อ [เติมฟอร์มพิมพ์](#เติมฟอร์มพิมพ์-formfillgs) ท้ายไฟล์)

ไฟล์ใน repo เป็นสำเนาสำหรับอ้างอิงและเก็บประวัติ — Apps Script ไม่ได้อ่านจาก repo
แก้ไฟล์ที่นี่แล้วต้องไปวางด้วยตัวเองในไฟล์ที่ **ตรงชื่อกัน** ของตัวแก้ไข Apps Script (ดูคำเตือนด้านล่าง)

## คำเตือนก่อนวางโค้ดใน Apps Script

วางโค้ดผิดไฟล์แล้วการสำรองข้อมูลเข้าชีตจะ **หยุดแบบเงียบๆ** เพราะ Pilot Web ยิงแบบ `no-cors`
(ดูหัวข้อ "รูปแบบข้อมูล") จึงมองไม่เห็นว่าล้มเหลว ผู้ใช้ไม่เห็นข้อความผิดพลาดใดๆ และชีตแค่ไม่มีแถวใหม่

**1. วางไฟล์ละที่เท่านั้น**

| ไฟล์ใน repo | วางที่ไหนใน Apps Script |
|---|---|
| `Code.gs` | ไฟล์ `Code.gs` |
| `FormFill.gs` | ไฟล์ `FormFill` — ถ้ายังไม่มี ให้สร้างด้วยปุ่ม **+** ข้าง Files > Script |

**2. ห้ามวาง `FormFill.gs` ทับ `Code.gs`** — `Code.gs` มี `doPost` ซึ่งเป็นตัวรับข้อมูลจากเว็บ
ถ้าถูกเขียนทับ การสำรองจะหยุดทันที หัวไฟล์ `FormFill.gs` ที่บอกให้ "ลบโค้ดเดิม วางโค้ดนี้แทน"
ใช้ได้เฉพาะเมื่อมีไฟล์ `FormFill` อยู่แล้ว ถ้าไม่มีให้สร้างไฟล์ใหม่ก่อน

**3. ห้ามวางไฟล์ฝั่งเว็บ** (`modules/module-mg.js`, `app.js`, `modules/*.js`) ใน Apps Script —
เป็นโค้ดที่รันในเบราว์เซอร์และใช้ไวยากรณ์ที่ตัวแก้ไข Apps Script ไม่รับ เช่น `??=`
อาการคือขึ้น `Syntax error: ParseError: Unexpected token = line: 97 file: Code.gs` และบันทึกไม่ได้
(`module-mg.js` บรรทัด 97 คือ `const modules = (window.MNP_REQUEST_MODULES ??= {});`)
`Code.gs` ที่ถูกต้องขึ้นต้นด้วยคอมเมนต์ "สำรองข้อมูลใบคำร้องถึงฝ่ายบริหาร (PP01-FM08)" และมี `function doPost(e)`

**4. ตรวจทุกครั้งหลังวางหรือ Deploy**

- ในไฟล์ `Code.gs` กด Ctrl+F ค้น `doPost` ต้องเจอ ถ้าไม่เจอแปลว่าตัวรับข้อมูลหายไป
- dropdown เลือกฟังก์ชันของตัวแก้ไข (ข้าง Run) แสดงเฉพาะฟังก์ชันของ **ไฟล์ที่เปิดอยู่** (สังเกตจากหน้าจอจริง)
  เปิด `Code.gs` ต้องขึ้น `doPost`, `doGet` และเปิด `FormFill` ต้องขึ้น `onOpen`, `onEdit`, `ffRefresh`, `ffClearForm`
  ให้เปิดดูทีละไฟล์หลังวาง
- ห้ามกด Save ขณะที่มีแถบแดง `Syntax error` ให้รีโหลดหน้าเพื่อทิ้งโค้ดที่วางผิด
  (ของเดิมที่บันทึกไว้ไม่เสียหาย)
- หลัง Deploy ให้ทดสอบจากเว็บจริงตามขั้นตอนใน "อัปเดตโค้ดเดิม" ข้อ 3 แล้วเปิดหน้า **Executions**
  ของ Apps Script ว่ามี `doPost` รันสำเร็จ — Web App ต้องยังเป็น deployment เดิม (URL ขึ้นต้น
  `AKfycbw_FQUW…` ตรงกับ `APPS_SCRIPT_MANAGEMENT_SYNC_URL` ใน `modules/module-mg.js`)

## Deploy

### ครั้งแรก

1. เปิดสเปรดชีตที่ลิงก์ด้านบน > เมนู **Extensions > Apps Script**
2. ลบโค้ดเริ่มต้นในไฟล์ `Code.gs` ที่ Apps Script สร้างให้ทิ้ง แล้ววางเนื้อหาจาก `Code.gs` ในโฟลเดอร์นี้แทน
3. **Deploy > New deployment** เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
4. กด Deploy แล้วคัดลอก URL ของ Web App ที่ได้
5. เปิด `modules/module-mg.js` หาตัวแปร `APPS_SCRIPT_MANAGEMENT_SYNC_URL` แล้ววาง URL ที่ได้ลงไป
6. เลื่อนเลข `?v=` ใน `index.html` ทุกจุด (`styles.css`/`app.js`/`modules/*.js`) ตามธรรมเนียมของ repo แล้ว push

### อัปเดตโค้ดเดิม (เช่นตอนที่เพิ่มชีตสรุปแบบมีคอลัมน์)

1. เปิดสเปรดชีต > **Extensions > Apps Script** > เปิดไฟล์ `Code.gs` แล้ววางเนื้อหา `Code.gs` ใหม่ทับของเดิมทั้งไฟล์
2. **Deploy > Manage deployments** > กดไอคอนดินสอ (แก้ไข) ที่ deployment เดิม > **Version: New version** > **Deploy**
   — ใช้ deployment เดิม **ไม่ต้องสร้างใหม่** เพื่อให้ URL เดิมใน `modules/module-mg.js` ยังใช้ได้ ไม่ต้องแก้อะไรที่ฝั่งเว็บ
   New version เผยแพร่ **ทั้งโปรเจกต์** ตามที่อยู่ในตัวแก้ไขตอนนั้น (ทุกไฟล์) ไม่ใช่เฉพาะไฟล์ที่เพิ่งแก้
   ถ้ามีการแก้ที่ยังไม่ตั้งใจเผยแพร่ค้างอยู่ จะถูกเผยแพร่ไปด้วย — ส่วนการแก้ `FormFill.gs` อย่างเดียว **ไม่ต้อง** Deploy
3. ทดสอบด้วยการเปิดหน้ารายละเอียดคำร้อง MANAGEMENT จริงในเว็บ แล้วเช็คว่าชีต **"ใบคำร้องถึงฝ่ายบริหาร"**
   มีแถวใหม่/อัปเดต — **ห้ามเชื่อผลจากการกด Run ในตัวแก้ไข Apps Script โดยตรง** เพราะตอนนั้น `e` (event
   ของ HTTP request) เป็น `undefined` โค้ดจะเข้า `catch` แล้วจบแบบ "Execution completed" ทันทีโดยไม่ได้
   รันโค้ดจริงเลย ต้องเป็น POST จริงจาก Pilot Web เท่านั้นถึงจะทดสอบได้ตรง

## รูปแบบข้อมูล

Pilot Web ยิง `fetch(url, { method: "POST", mode: "no-cors", body: JSON.stringify({ batch: [...] }) })`
ทุกครั้งที่มีคนเปิดหน้ารายละเอียดคำร้องประเภทนี้ (ดู `syncManagementOrderToAppsScript`
ใน `modules/module-mg.js`) — เพราะเป็น `no-cors` จึงอ่าน response กลับไม่ได้และแนบ header/token ไม่ได้ (เหมือนสคริปต์
ใบแจ้งซ่อมเดิมทุกประการ) **ต้องตั้ง Access เป็น "Anyone" และถือ URL นี้เป็นความลับระดับหนึ่ง (เหมือน webhook)**

Body:

```json
{ "batch": [{ "key": "mgmt:<request-id>", "value": "<JSON string ของ order>" }] }
```

โครงสร้างของ `order` (หลัง parse ค่า `value`):

| ฟิลด์ | ความหมาย |
|---|---|
| `id`, `docNumber` | Supabase request id / request_no |
| `department` | รหัสแผนกของผู้ยื่น |
| `subject`, `description`, `attachmentNote` | เรื่อง / รายละเอียด / สิ่งที่แนบมาด้วย |
| `requestedBy`, `position`, `submittedAt` | ผู้ยื่นคำร้อง / ตำแหน่ง / วันที่ยื่น |
| `status` | `PENDING_FM` / `PENDING_GM` / `NEEDS_INFO` / `APPROVED` / `IN_PROGRESS` / `DONE` / `REJECTED` / `ACKNOWLEDGED` |
| `decision` | มติที่ขั้นล่าสุดที่ตัดสินแล้ว: `approved` / `rejected` / `acknowledged` / `""` (ยังไม่มีมติ) |
| `comment` | บันทึกข้อคิดเห็นฝ่ายบริหารของขั้นที่ตัดสิน |
| `approvals.fm` / `approvals.gm` | สถานะ/ผู้ลงนาม/วันที่/หมายเหตุ ของฝ่ายบริหารโรงงาน และผู้จัดการทั่วไป |
| `ccDepartments`, `ccOther` | รหัสแผนกที่สำเนาถึง + ข้อความช่อง "อื่นๆ" |

สคริปต์นี้เก็บข้อมูล 2 ชั้น (สร้างชีตอัตโนมัติถ้ายังไม่มี):

- **"Log"** — 3 คอลัมน์ `key`, `value` (JSON string ดิบ), `updatedAt` — upsert ทับแถวเดิมด้วย
  `key` เดียวกัน ไว้เป็นสำเนาตั้งต้น/ใช้ debug
- **"ใบคำร้องถึงฝ่ายบริหาร"** — แกะฟิลด์จาก `value` มาลงคอลัมน์ที่มีชื่อ อ่านง่ายแบบเดียวกับชีต
  "ใบแจ้งซ่อม" ของสคริปต์เดิม upsert ทับแถวเดิมด้วย**เลขที่เอกสาร** (คอลัมน์แรก): เลขที่เอกสาร, แผนก,
  เรื่อง, รายละเอียด, สิ่งที่แนบมาด้วย, ผู้ยื่นคำร้อง, ตำแหน่ง, ยื่นเมื่อ, สถานะ, มติ, ความเห็น,
  ผจก.โรงงาน อนุมัติโดย/เมื่อ, ผจก.ทั่วไป อนุมัติโดย/เมื่อ, สำเนาถึงแผนก, สำเนาอื่นๆ, อัปเดตล่าสุด

## เติมฟอร์มพิมพ์ (`FormFill.gs`)

เติมข้อมูลลงฟอร์ม PP01-FM08 ในชีต **"เอกสาร"** จากแถวของชีต **"ใบคำร้องถึงฝ่ายบริหาร"** เพื่อพิมพ์ออกมาเซ็นเป็นกระดาษ
ไม่เกี่ยวกับ Web App ที่ Pilot Web เรียก — ไฟล์นี้ไม่รับข้อมูลจากเว็บและไม่เขียนชีตข้อมูล

### ติดตั้ง

1. เปิดสเปรดชีต > **Extensions > Apps Script** (โปรเจกต์เดียวกับ `Code.gs`)
2. เพิ่มไฟล์ Script ชื่อ `FormFill` (ปุ่ม **+** ข้าง Files) แล้ววางเนื้อหาจาก `FormFill.gs` > **Save**
   — **ห้ามวางทับ `Code.gs`** (ดู "คำเตือนก่อนวางโค้ดใน Apps Script")
3. ปิดแล้วเปิดสเปรดชีตใหม่ เมนู **ใบคำร้อง** จะขึ้นที่แถบเมนู

อัปเดตเวอร์ชันของ FormFill ที่มีอยู่แล้ว: เปิดไฟล์ `FormFill` > เลือกทั้งหมด > วางทับ > **Save** (ทำกับไฟล์ `FormFill` เท่านั้น)
ครั้งแรกที่สั่งงานจากเมนู Google จะขอสิทธิ์ ให้อนุญาต (สคริปต์ของเราเอง จึงอาจขึ้นว่ายังไม่ได้ตรวจสอบ)

ไม่ต้องแก้ `Code.gs` และ **ไม่ต้อง Deploy ใหม่** — `onOpen`/`onEdit` ทำงานจากโค้ดที่บันทึกแล้ว ส่วน URL ของ Web App
(ที่ผูกกับเวอร์ชันที่ Deploy ไว้) ไม่เปลี่ยน

### ใช้งาน

- พิมพ์เลขที่เอกสาร (เช่น `FT 004/26`) ที่เซลล์ **AD3** ของชีต "เอกสาร" → ฟอร์มถูกเติมตามแถวที่ตรงกัน
  เลขที่ต้องตรงกับคอลัมน์ "เลขที่เอกสาร" (ไม่สนตัวพิมพ์เล็ก/ใหญ่ แต่ช่องว่างกลางเลขต้องตรง)
- ลบค่าใน AD3 หรือใส่เลขที่ที่ไม่พบ → ฟอร์มกลับเป็นแบบฟอร์มเปล่า (กรณีไม่พบจะมีข้อความแจ้ง)
- เมนู **ใบคำร้อง > ดึงข้อมูลใหม่** ใช้เติมซ้ำเมื่อข้อมูลต้นทางเปลี่ยน (เช่น อนุมัติแล้ว) และ **ล้างฟอร์ม** คืนเป็นแบบฟอร์มเปล่า
- ถ้าพิมพ์เลขที่แล้วขึ้น "ไม่พบเลขที่เอกสาร" แปลว่าแถวนั้นยังไม่ถูกสำรองลงชีต "ใบคำร้องถึงฝ่ายบริหาร"
  (การสำรองเกิดเมื่อมีคนเปิดหน้ารายละเอียดคำร้องใน Pilot Web — ดูหัวข้อ "รูปแบบข้อมูล")

### พฤติกรรมที่ควรรู้

- หาช่องในฟอร์มจาก **ข้อความหัวข้อ** ทุกครั้งที่รัน (ไม่ fix ตำแหน่งเซลล์) จึงย้าย/แทรกแถวในฟอร์มได้
  แต่ถ้าแก้ข้อความหัวข้อ สคริปต์อาจหาช่องไม่เจอ และจะแจ้ง "หาช่องในฟอร์มไม่เจอ: …" แทนที่จะเขียนผิดที่
- มติ: `approved` → ติ๊ก "อนุมัติ", `rejected` → "ไม่อนุมัติ", `acknowledged` → "ได้รับทราบ" (แก้ได้ที่ `FF_DECISION_MAP`)
- "วันที่ออกเอกสาร" และ "วันที่ยื่น" ใช้ค่าจากคอลัมน์ "ยื่นเมื่อ" แสดงเป็นเวลาไทย ปี ค.ศ.
  (ตั้ง `FF_USE_BUDDHIST_YEAR = true` เพื่อแสดง พ.ศ.)
- ลายเซ็นและวันที่ของ ผจก.โรงงาน / ผจก.ทั่วไป จะเติมเฉพาะขั้นที่มีผู้อนุมัติแล้ว ขั้นที่ยังไม่ลงชื่อคงเป็นเส้นว่างของแบบฟอร์ม
- ส่วนที่ 3 ติ๊กแผนกที่อยู่ในคอลัมน์ "สำเนาถึงแผนก" และเติมช่อง "อื่นๆ" จาก "สำเนาอื่นๆ"
  ป้ายในฟอร์มที่ไม่ตรงกับรหัสแผนกที่ระบบเก็บต้องมีใน `FF_CC_LABEL_TO_CODE` (ตอนนี้มี `ธุรการ FT` → `FT`)
  เทสต์จะล้มถ้ารหัสในฟอร์มกับตารางสำเนาถึงของเว็บ (`modules/module-mg.js`) ไม่ตรงกัน
- **ช่องติ๊ก**: ฟอร์มมีช่องสี่เหลี่ยม (checkbox) จริงอยู่ทางซ้ายของ "อนุมัติ/ไม่อนุมัติ/รับทราบ" และของแต่ละแผนก
  สคริปต์ติ๊ก checkbox นั้น และคงป้ายเป็นข้อความธรรมดา (ไม่พิมพ์ ☑ ซ้ำ) ถ้าหา checkbox ไม่พบจึงใช้ ☑/☐ ในข้อความแทน
- **รายละเอียดและบันทึกข้อคิดเห็น** ตัดข้อความเป็นบรรทัดแล้วใส่ทีละแถวตามเส้นของฟอร์ม
  (รายละเอียด: จากแถวหัวข้อถึงแถวก่อน "ผู้ยื่นคำร้อง", ความเห็น: จากแถวหัวข้อถึงก่อนแถวลายเซ็น 2 แถว) ไม่ merge เซลล์
  เพราะเส้นบรรทัดอยู่ที่ขอบล่างของแต่ละแถวและจะหายถ้า merge ย่อหน้าที่ขึ้นบรรทัดใหม่ในต้นฉบับขึ้นบรรทัดใหม่เสมอ
  ถ้ายังไม่พอจะย่อตัวอักษรลงทีละ 1pt (ไม่ต่ำกว่า `FF_MIN_FONT`) และตัดท้ายพร้อมแจ้งเตือนเป็นทางสุดท้าย
  **รายละเอียด** เริ่มเนื้อหาบรรทัดแรกที่เซลล์ H ของแถวหัวข้อ (`bodyOffset: 5` ใน `FF_FIELDS` นับจากคอลัมน์ของหัวข้อ)
  คำว่า "รายละเอียด" คงเป็นข้อความของแบบฟอร์ม ไม่ถูกเขียนทับและไม่ซ้ำหน้าเนื้อหา บรรทัดต่อไปเริ่มที่คอลัมน์ของหัวข้อ
  ส่วน **ความเห็น** เขียนต่อท้ายหัวข้อในเซลล์เดียวกัน (ไม่ระบุ `bodyOffset`)
- **ช่องบรรทัดเดียว** (เรื่อง, สิ่งที่แนบ, ผู้ยื่น, แผนก, ตำแหน่ง, วันที่ยื่น, สำเนาอื่นๆ) ย่อตัวอักษรให้พอดีช่อง
  ช่องของหัวข้อหนึ่งยาวถึงหัวข้อถัดไปในแถวเดียวกัน หรือถึงขอบขวาของฟอร์ม (`FF_RIGHT_COL`) ตัวอักษรกลับเป็นขนาดปกติเมื่อเติมใบใหม่
  ขนาดปกติของแต่ละช่องอยู่ที่ `size`/`lineSize` ใน `FF_FIELDS` ตามฟอร์มปัจจุบัน
- บรรทัดต่อของรายละเอียด/ความเห็น และบรรทัดแรกของรายละเอียด (เซลล์ H) ขึ้นต้นด้วยอักขระล่องหนตัวเดียว (U+200B, `FF_CONT`) เพื่อไม่ให้สคริปต์เข้าใจว่าข้อความ
  ที่ขึ้นต้นด้วยคำว่า "เรื่อง" "ตำแหน่ง" ฯลฯ เป็นหัวข้อของฟอร์ม และไม่ให้ข้อความที่ขึ้นต้นด้วย `=` ถูกตีความเป็นสูตร
  ข้อความที่คัดลอกจากบรรทัดเหล่านี้จึงมีอักขระล่องหนติดไปด้วย
- v2 ล้างข้อความที่ v1 เคยเขียนผิดแถวให้เอง (เฉพาะเซลล์ที่ v1 เคยเขียนและเนื้อหาเป็นของ v1)
- ข้อความจากคำร้องขึ้นต้นด้วยหัวข้อของช่องหรืออักขระล่องหนเสมอ จึงไม่ถูกตีความเป็นสูตร (เช่น เรื่องที่ขึ้นต้นด้วย `=`)

### ข้อจำกัดที่ทราบ

- FormFill อ่านชีตข้อมูลตาม **ชื่อหัวคอลัมน์** ที่ `STRUCTURED_HEADERS` ใน `Code.gs` กำหนด
  ถ้าเปลี่ยนชื่อ/เพิ่มคอลัมน์ใน `Code.gs` ต้องแก้ `FormFill.gs` ให้ตรงกันด้วย
- **ความกว้างของตัวอักษรเป็นค่าประมาณ**: Apps Script วัดความกว้างข้อความจริงไม่ได้ สคริปต์อ่านความกว้างคอลัมน์จริงจากชีต
  แล้วประมาณจำนวนตัวอักษรต่อบรรทัดจาก `FF_CHAR_EM` (ค่าเริ่มต้น 0.42 เท่าของขนาดฟอนต์ AngsanaUPC จริงราว 0.35 จึงเผื่อไว้)
  ถ้าบรรทัดยังล้นขอบ ให้เพิ่มค่านี้ ถ้าบรรทัดสั้นเกินไป ให้ลดค่านี้ — เมื่อเปลี่ยนฟอนต์ของแบบฟอร์มให้ตรวจใหม่
- ตำแหน่งที่สคริปต์ถือเป็นขอบฟอร์มและบรรทัดมีเส้น (`FF_RIGHT_COL` = AK, ความสูงของพื้นที่รายละเอียด/ความเห็นตามแถวหัวข้อ
  ถัดไป) อ่านจากแบบฟอร์มปัจจุบัน ถ้าเพิ่ม/ลดแถวเส้นในแบบฟอร์ม ให้ตรวจ `block.until` และ `block.gap` ใน `FF_FIELDS`
- การเติมฟอร์มเรียกบริการของ Google หลายสิบครั้ง ใช้เวลาไม่กี่วินาทีต่อครั้ง (`onEdit` มีเวลาจำกัด 30 วินาที)

### ทดสอบ

`npm run test:unit` มี `scripts/tests/management-formfill.test.mjs` โหลด `Code.gs` และ `FormFill.gs` เข้า vm เดียวกัน
จำลองชีตตามเลย์เอาต์จริงของฟอร์ม (ตรวจจากไฟล์ที่ส่งออกจาก Google Sheets) ตรวจการเติม/ล้างฟอร์ม การตัดบรรทัดและการย่อตัวอักษร
ช่องติ๊ก และตรวจว่าสองไฟล์ไม่ประกาศชื่อ global ซ้ำกัน (ซึ่งจะทับโค้ดของ Web App เงียบๆ)
สิ่งที่ต้องทดสอบมือบน Google จริง: เมนู, `onEdit`, ความกว้างตัวอักษรจริงของ AngsanaUPC และการพิมพ์ออกกระดาษ
