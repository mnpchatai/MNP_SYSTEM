# สำเนา NCR ลงสเปรดชีต NCR/CAR (QA02-FM01)

Google Apps Script สำหรับสเปรดชีต [NCR/CAR](https://docs.google.com/spreadsheets/d/1_F2lxC51hVFckTUoUBzBpnQI-CVnIJuauDztwfINXGQ/edit)
เป็นแค่สำเนาสำรอง/รายงาน — **Supabase ยังเป็นฐานข้อมูลหลักและเป็นตัวบังคับสิทธิ์/ขั้นตอนทั้งหมด**
ใช้รูปแบบเดียวกับสคริปต์สำรองใบแจ้งซ่อมและ `apps-script/management-backup`

ทำ 2 อย่าง:

1. **ส่งข้อมูลจาก Web App ลงชีต "รายงานNCR"** — Pilot Web (`modules/ncr-sheet-sync.js`) ยิงข้อมูลใบ NCR
   มาทุกครั้งที่หน้ารายละเอียด NCR ถูกวาด ซึ่งเกิดหลังกด "ออก NCR" และหลังส่งทุกขั้นตอน (พิจารณา ตอบ ติดตามผล
   ลงนาม ฯลฯ) สคริปต์ upsert หนึ่งแถวต่อใบตั้งแต่แถวที่ 4 โดยใช้เลขที่ใบ NCR (คอลัมน์ A) — สถานะในชีตจึงอัปเดตตามขั้นล่าสุด
2. **ใส่เลขที่เอกสารที่ช่อง X2 ของชีต "เอกสารNCR" แล้วดึงข้อมูลลงฟอร์ม** — trigger `onEdit` เติมทุกช่องของฟอร์ม
   QA02-FM01 (ส่วนที่ 1-4 เช็คบ็อกซ์ ชื่อผู้ลงนาม และวันที่) ลบเลขที่ออก = ล้างฟอร์มกลับเป็นแบบฟอร์มเปล่า
   มีเมนู **NCR** ในสเปรดชีตสำหรับดึงซ้ำ/ล้างฟอร์มด้วย

### ข้อมูลโหมดทดสอบ

ใบในโหมดทดสอบของ admin (`is_test` เลขที่ขึ้นต้น `TEST-`) ถูกส่งมาพร้อม `isTest: true` ส่วนจะรับหรือไม่ขึ้นกับ
`ACCEPT_TEST_REPORTS` ใน `Code.gs` (ตอนนี้ `true` เพื่อทดลองระบบก่อนใช้ข้อมูลจริง) แถวทดสอบมีป้าย **[ทดสอบ]**
นำหน้าสถานะในชีตรายงานNCR และใส่เลขที่ `TEST-…` ที่ X2 เพื่อดึงลงฟอร์มได้เหมือนใบจริง

เลิกทดลองแล้ว:

1. แก้ `ACCEPT_TEST_REPORTS` เป็น `false` แล้ว Deploy เวอร์ชันใหม่ (ตามหัวข้อ "อัปเดตโค้ดเดิม")
2. เมนู **NCR > ลบข้อมูลทดสอบ (TEST-) ทั้งหมด** — ลบเฉพาะแถวที่เลขที่ขึ้นต้น `TEST-` ใบจริงไม่ถูกแตะ

## Deploy

### ครั้งแรก

1. เปิดสเปรดชีตที่ลิงก์ด้านบน > เมนู **Extensions > Apps Script**
2. ลบโค้ดเริ่มต้นในไฟล์ `Code.gs` แล้ววางเนื้อหาจาก `Code.gs` ในโฟลเดอร์นี้แทน
   (ถ้าโปรเจกต์มี `onEdit`/`onOpen` อยู่แล้วในไฟล์อื่น ต้องรวมเป็นฟังก์ชันเดียว เพราะชื่อซ้ำกันไม่ได้)
3. **Project Settings** > Time zone ตั้งเป็น `(GMT+07:00) Bangkok`
4. **Deploy > New deployment** เลือกประเภท **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
5. กด Deploy อนุญาตสิทธิ์ แล้วคัดลอก URL ของ Web App (ลงท้าย `/exec`)
6. เปิด `modules/ncr-sheet-sync.js` ใส่ URL ในตัวแปร `SYNC_URL`
7. เลื่อนเลข `?v=` ใน `index.html` ทุกจุดตามธรรมเนียมของ repo แล้วเปิด pull request

ก่อนใส่ URL (ข้อ 6) ฝั่งเว็บจะไม่ส่งอะไรเลย การ deploy สคริปต์ก่อนจึงไม่กระทบผู้ใช้

### อัปเดตโค้ดเดิม

1. วางเนื้อหา `Code.gs` ใหม่ทับของเดิมทั้งไฟล์
2. **Deploy > Manage deployments** > ไอคอนดินสอที่ deployment เดิม > **Version: New version** > **Deploy**
   — ใช้ deployment เดิมเพื่อให้ URL เดิมใน `modules/ncr-sheet-sync.js` ยังใช้ได้

### ทดสอบ

- เปิดหน้ารายละเอียด NCR จริงในเว็บ แล้วเช็คว่าชีต **รายงานNCR** มีแถวของใบนั้น และชีตซ่อน **NCR_DATA** มีข้อมูล
- พิมพ์เลขที่ใบนั้นในช่อง X2 ของชีต **เอกสารNCR** แล้วดูว่าฟอร์มถูกเติม
- **อย่าเชื่อผลการกด Run `doPost`/`onEdit` ในตัวแก้ไข Apps Script** เพราะตอนนั้นไม่มี `e` จริง
  ต้องทดสอบด้วย POST จริงจาก Pilot Web และการพิมพ์ในชีตจริงเท่านั้น

## รูปแบบข้อมูล

```json
{ "batch": [{ "key": "ncr:<ncr_reports.id>", "value": "<JSON string ของ record>" }] }
```

`record` สร้างโดย `buildRecord` ใน `modules/ncr-sheet-sync.js` (มี unit test ที่
`scripts/tests/ncr-sheet-sync.test.mjs`) วันที่ทั้งหมดเป็น `YYYY-MM-DD` ตามเวลาไทย ชื่อคนแปลงเป็นชื่อ-นามสกุลแล้ว

## การจับคู่ข้อมูล

### ชีต "รายงานNCR" (NCR LOG)

| คอลัมน์ | ข้อมูล |
|---|---|
| A เลขที่ใบ NCR | `ncr_no` |
| B วันที่ออกใบ NCR | `issue_date` |
| C ผู้ออก NCR / แผนก | ชื่อผู้รายงาน / แผนกตอนออกใบ |
| D ชื่อผลิตภัณฑ์/วัตถุดิบ | ชื่อสินค้า (รหัส) |
| E รายละเอียด | `description` |
| F-L สาเหตุ (บุคลากร … อื่นๆ) | ✓ ตามสาเหตุ 4M ที่แผนกเลือก |
| M แนวทางการแก้ไข / N แนวทางการป้องกัน | `correction` / `prevention` |
| O แผนกที่รับ NCR / พ่อค้า | แผนกที่รับผิดชอบ + ชื่อพ่อค้าเมื่อเลือก "ส่งคืนพ่อค้า" |
| P ว/ด/ป ที่แก้ไขเสร็จ | กำหนดเสร็จของแนวทางแก้ไข (ระบบยังไม่เก็บวันที่แก้เสร็จจริงแยก) |
| Q ว/ด/ป ที่ตรวจติดตาม | วันที่ QA ติดตามผล |
| R ผู้รับผิดชอบการแก้ไข | ผู้ตอบส่วนที่ 3 |
| S สถานะของ NCR | ป้ายสถานะเดียวกับหน้าเว็บ |
| T ว/ด/ป ที่ปิด NCR | `closed_at` |

### ชีต "เอกสารNCR"

ตำแหน่งช่องทั้งหมดอยู่ในค่าคงที่ช่วงต้นของ `Code.gs` (`SOURCE_CHECKBOXES`, `TEXT_CELLS`, `LINE_FIELDS`,
`TEMPLATE_TEXT` ฯลฯ) ถ้าย้ายช่องในแบบฟอร์มให้แก้ที่นั่นที่เดียว ข้อความยาว (รายละเอียด สาเหตุ แนวทางแก้ไข/ป้องกัน)
ถูกแบ่งลงทีละบรรทัดตาม `maxChars` ถ้ายาวเกินจำนวนบรรทัดของฟอร์มจะตัดท้ายด้วย "…" (ข้อความเต็มดูได้ในเว็บและชีต
รายงานNCR) ช่อง "ออก CAR" ล้างเป็นว่างเสมอจนกว่าระบบจะมี CAR (Phase 2)

ถ้าเลขที่ที่ใส่ไม่มีใน `NCR_DATA` (เช่น แถวที่กรอกมือในรายงานNCR ก่อนใช้ระบบ) สคริปต์ดึงเท่าที่ชีตรายงานNCR มี

## ความปลอดภัย

- Web App ต้องเปิด **Anyone** เพราะ `fetch` แบบ `no-cors` แนบ token ไม่ได้ — ถือ URL เป็นความลับระดับ webhook
- สคริปต์รับเฉพาะ key `ncr:<uuid>` ที่ตรงกับ `id` ใน record, ใบทดสอบต้องมีเลขที่ `TEST-…` (และใบจริงห้ามขึ้นต้น `TEST-`) และจำกัดขนาดข้อมูล
- ข้อความทุกช่องเขียนเป็นข้อความล้วน ข้อความที่ขึ้นต้นด้วย `= + - @` ถูกเติม `'` นำหน้า กันการกลายเป็นสูตร
- ใช้ `LockService` กันการส่งพร้อมกันแล้วเกิดแถวซ้ำ
