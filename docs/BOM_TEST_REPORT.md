# รายงานทดสอบทั้งระบบ BOM และ RubberFlow (โหมดทดสอบ)

ทดสอบเมื่อ 17 พ.ย. 2569 บน localhost (Pilot harness พอร์ต 5186, Supabase จำลอง `scripts/pilot-harness-mock.mjs`) จาก `origin/main` = `576b511` (หลัง merge #376) ไม่ได้แตะฐานข้อมูลจริง ไม่ได้แก้โค้ด ข้อมูลตั้งต้น = ชุดสาธิต `MNP_BOM_SEED` + `MNP_RUBBERFLOW_SEED` ตามตัวสร้างชุดทดสอบของ session ก่อน แล้วสร้างสินค้า ใบสั่งผลิต และ WO ใหม่ด้วยการกดจริงตามบทบาท (ฝ่ายวางแผน PP, RB, หัวหน้า RB, GR, ST, SR, QA, WH, หัวหน้า WH, admin)

## คำตัดสิน

**ยังไม่พร้อมให้พนักงานจริงใช้เต็มรูปแบบ** แต่ใกล้แล้ว: เส้นทางหลักตั้งแต่สร้างสินค้า → ใบสั่งผลิต → สั่งซื้อ → ปล่อยผลิต → RubberFlow → รายงานผล → รับเข้าคลัง → ส่งมอบ เดินได้ครบ ตัวเลขที่คิดมือเทียบแล้วถูกทุกจุดที่ตรวจ และสิทธิ์ตามบทบาทกันได้ถูก เหตุผลหลักสามข้อที่ยังไม่ควรปล่อย: (1) **ยกเลิกใบสั่งผลิตมีทางตัน**: ถ้า WO ใน RubberFlow เริ่มผลิตแล้ว ใบยกเลิกไม่ได้เลย ข้อความบอกให้ไปยกเลิก WO แต่ RubberFlow ไม่มีปุ่มนั้น และกลับกัน ถ้า WO เพิ่งเบิกเคมีไปแล้ว ใบยกเลิกได้ แต่เคมีหายจากสต็อกโดยไม่มีทางคืน (2) **ยอดผลิตผิดได้โดยไม่มีใครเตือน**: งาน RB ที่ผูก WO ยังกด "รายงานผล" เองได้ (นับซ้ำกับ RubberFlow) แผนกรายงานเกินของที่แผนกก่อนส่งมาได้ และบรรทัดเส้นยางใส่ปริมาณขัดกับข้อมูลการตัดได้ (3) **รับของจากใบสั่งซื้อไม่ครบ ยอดที่ขาดหายไปเลย** ระบบไม่จำว่ายังค้างรับ ทำให้ต้องสั่งใหม่และเห็นยอดขาดซ้ำ ข้อ 1 และ 3 ต้องมี migration และต้องให้คุณตัดสินกติกาก่อน ถ้าแก้ชุดที่ 1–2 ด้านล่างแล้ว ลองนำร่องกับฝ่ายวางแผน ST และ WH ได้

## ข้อบกพร่อง เรียงตามความรุนแรง

ขนาด: เล็ก = ไม่เกินครึ่งวัน · กลาง = หนึ่งถึงสองวัน · ใหญ่ = มากกว่านั้น · "client" = แก้หน้าจออย่างเดียว · "migration" = ต้องแก้ฐานข้อมูลและขออนุมัติก่อนใช้กับฐานข้อมูลจริง

ทุกข้อทำซ้ำได้อย่างน้อยสองครั้ง ข้อที่ขึ้นกับกติกาฝั่งเซิร์ฟเวอร์ ตรวจ SQL ใน `supabase/migrations/` แล้ว และ mock ทำเหมือน SQL (ดูหัวข้อ ข)

### ทำงานต่อไม่ได้

**B1 ใบสั่งผลิตที่ WO เริ่มผลิตแล้ว ยกเลิกไม่ได้ทุกทาง และข้อความชี้ไปทางที่ไม่มี**
- ขั้นตอน: ปล่อยผลิต DEMO-26005 → หัวหน้า RB ปล่อย WO-20261117-02 → RB เบิกเคมีและบันทึกผสม (WO เป็น "กำลังผลิต") → PP กด "ยกเลิกใบ"
- ผล: "มีงานที่สร้าง WO ใน RubberFlow แล้ว (WO-20261117-02) ยกเลิก WO ใน RubberFlow ก่อน" แต่หน้า WO ที่กำลังผลิตมีแค่ "พัก / ปิดงาน" ไม่มี "ยกเลิก" ลองกด "ปิดงาน" WO (เป็น completed) แล้วยกเลิกใบอีกครั้ง ได้ข้อความเดิม
- ที่ควรเป็น: มีทางยกเลิกหรือปิดใบที่ลูกค้ายกเลิกหลังเริ่มผลิตแล้ว
- หลักฐาน SQL: `private.bom_cancel_rf_orders` (20261108020000:234-270) ปฏิเสธ `BOM_RF_ORDER_STARTED` เมื่อ WO เป็น in_progress, on_hold หรือ completed
- วิธีแก้ที่เสนอ (ต้องให้คุณตัดสินกติกาก่อน): ยอมให้ยกเลิกเมื่อ WO ที่ผูกปิดหรือยกเลิกแล้ว พร้อมเหตุผล และแก้ข้อความให้บอกวิธีที่ทำได้จริง หรือทางสำรองที่มีอยู่แล้ว: ฝ่ายวางแผนปิดงานที่เหลือพร้อมเหตุผล แล้ว WH "ปิดใบ (รับไม่ครบ)" ซึ่งต้องบอกในข้อความ · migration · กลาง

### ผลผิด

**W1 ยกเลิกหรือเปิดใบกลับมาแก้ หลัง WO เบิกเคมีไปแล้ว เคมีหายจากสต็อก**
- ขั้นตอน: ปล่อย 261117-26007 → หัวหน้า RB ปล่อย WO-20261117-08 → RB เบิกเคมี REQ-20261117-04 (จ่ายจริงประมาณ 60 กก.) → PP ยกเลิกใบ
- ผล: ยกเลิกสำเร็จ WO ทั้ง 3 ใบเป็น cancelled แต่ใบเบิกยังเป็น "จ่ายแล้ว" เคมีไม่กลับเข้าสต็อก ใบเบิกนี้ยังอยู่ในรายการของหน้าผสมยาง กดบันทึกแล้วได้ "ใบสั่งผลิต WO-20261117-08 ถูกยกเลิกแล้ว บันทึกการผลิตไม่ได้" กล่องยืนยันการยกเลิกก็ไม่ได้บอกว่ามีเคมีจ่ายไปแล้ว
- หลักฐาน SQL: `bom_cancel_rf_orders` ยกเลิก WO สถานะ planned และ released ได้ ไม่แตะ `rf_requisitions` ไม่มีโค้ดใดคืนยอดใบเบิก การเปิดใบกลับด้วย `updateOrderItem` เป็นแบบเดียวกัน
- วิธีแก้: นับ WO ที่มีใบเบิก issued เป็น "เริ่มแล้ว" (ปฏิเสธพร้อมบอกเลขใบเบิก) หรือคืนเคมีเข้าล็อตเดิมตอนยกเลิก (ต้องตัดสิน) และซ่อนใบเบิกของ WO ที่ยกเลิกจากหน้าผสม · migration · กลาง

**W2 รับของตามใบสั่งซื้อไม่ครบ ส่วนที่ขาดหายจากยอดสั่งค้างรับ**

- ผล: บรรทัดนั้นถือว่ารับแล้ว ปุ่มหาย ยอด 27.25 ที่ผู้ขายยังไม่ส่งไม่นับเป็น "สั่งแล้วรอรับ" ใบร่าง DEMO-26005 กลับมาขาด 17.25 กล่อง ST จะเห็นการ์ดให้สั่งใหม่
- ที่ควรเป็น: ส่วนที่ยังไม่ส่งยังค้างรับ รับได้อีก หรือ ST เลือกว่า "ปิดส่วนที่เหลือ"

**W3 งาน RB ที่ผูก WO แล้ว ยังรายงานผลด้วยมือได้ ยอดนับซ้ำกับ RubberFlow**

## ตัวเลขที่ตรวจด้วยมือ

สินค้า QA-RING-01(P)-A × 100: WIP 1 ชุด/FG → ชิ้นยาง GR 2 ชิ้น/WIP → เส้นยาง 0.1 เส้น/ชิ้น (10 ชิ้นต่อเส้น) · ถุง 1 กก./WIP · กล่อง 0.5/FG

- ไม่นับของในไลน์: WIP 100, GR 200, เส้นยาง 200 × 0.1 = 20, ถุง 100 กก., กล่อง 50 → ตรง
- นับ WIP 10 และ GR 20: WIP 90 → GR 90 × 2 = 180 − 20 = 160 → เส้นยาง 16 → ถุง 90 กก. → ตรงกับหน้าจอ งาน และ CSV
- WO: 16 เส้น × 0.5 กก. × 1.05 (เผื่อเสีย 5%) = 8.4 กก. → ตรง
- เคมี (สูตร RC-NBR-OR02 รวม 171 PHR, batch 40 กก. เบิกเต็ม batch): ZnO = 40 × 5 / 171 = 1.170 กก., NBR = 40 × 100 / 171 = 23.392 กก. → ตรง
- ยอดขาดถุงในขั้น 2: 90 − (10 − 0.3) = 80.3 → ตรง · กล่อง 50 − (5 − 27.25) − 5 = 67.25 → ตรง (แต่ดู U2)
- เบิกของซื้อ: กล่อง 55 − 52 = 3, คืน 2 → 5, ยกเลิกการเบิก → 55 · ถุง 90.3 − 60 = 30.3 → ตรง
