# แผนโมดูลรายแผนกของฝ่ายโรงงาน

เขียนเมื่อ 2026-11-19 จากโค้ดที่ `origin/main` = `462badd` (หลัง merge #389) แผนนี้ใช้แทนทิศทางเดิมที่รวมงานทุกแผนกไว้ในโมดูล BOM กับ RubberFlow ส่วน `docs/BOM_NEXT_PLAN.md` เหลือใช้เฉพาะหัวข้อวิธีทำงานกับ agent

ผังงานอ้างอิง: 01 ฝ่ายขาย → 02 ฝ่ายวางแผน → 03 ST → 04 RB → 05 SR + 06 QC → 07 GR → 08 PT และ 09 BG (ขนาน) → 10 PK → 11 WH (`rules.PROCESS_FLOW` ใน `modules/bom-rules.js`)

## หลักที่เจ้าของสั่ง

1. **ทุกแผนกมีโมดูลของตัวเอง** มีรายการของตัวเองในเมนูหลัก เปิดเข้าไปเจอพื้นที่ทำงานของแผนกนั้น ไม่ฝากไว้ในเมนูของโมดูลอื่น
2. **RubberFlow เป็นของแผนก RB เท่านั้น** งานของแผนกอื่นที่อยู่ในนั้นต้องย้ายออก
3. **โมดูลคลัง (SR, ST, WH) เริ่มที่ "ในคลังมีอะไรบ้าง"** ชี้บ่งได้ทีละรายการ แล้วจึงเป็นงานรับเข้า ตรวจ และจ่ายออก
4. **ใช้คำตามผังงาน** เช่น "ยางเส้นยาว" และ "คลังยางเส้นยาว" ไม่ใช่ "แท่งยาว"
5. **ทั้งหมดอยู่ในโหมดทดสอบ** จนกว่าเจ้าของสั่งเปิดใช้จริงทั้งโรงงานด้วยประโยคชัดเจน (สวิตช์ `REAL_STAFF_OPEN` และ `bom_real_open()` ห้ามแตะ)

## สภาพวันนี้ (ตรวจจากโค้ด)

- โมดูลโรงงานมี 2 ตัว คือ BOM (`#/bom`) และ RubberFlow (`#/rubberflow`) ทุกแผนกใช้ร่วมกัน ยังไม่มีโมดูลรายแผนกเลย
- ฝ่ายขายไม่มีหน้าหรือบทบาทของตัวเอง พนักงานฝ่ายขายถูกจัดเป็นผู้ดูอย่างเดียว
- GR, PT, BG, PK มีแค่การ์ดงานและหน้าต่างรายงานผลในหน้า "งานของฉัน" ของ BOM
- SR มีหน้า "คลังแท่งยาว (SR)" หน้าเดียวใต้ "งานของฉัน" ของ BOM ออกแบบตามใบสั่งผลิต ไม่มีการค้นหา ตำแหน่งจัดเก็บ หรือป้าย และรับยางเข้าคลังได้ทางเดียวคือจากล็อตตกแต่งของใบสั่งผลิต
- RubberFlow มีงานของ ST (คลังวัตถุดิบ ใบสั่งซื้อ รับคืนเคมี) SR (รับมอบ WIP) QA (QC NCR CoA SPC) WH (สินค้าสำเร็จรูป ส่งกล่อง) และฝ่ายวางแผน (เปิดและปล่อยใบสั่งผลิตยาง) ปนอยู่
- โมดูลใหม่ใช้ข้อมูลเดิมได้โดยไม่ต้องย้ายข้อมูล: หน้าใหม่อ่านและสั่งงานผ่าน `window.MNP_BOM.store` และ `window.MNP_RUBBERFLOW` ได้ สิทธิ์จริงตัดสินที่ฐานข้อมูลเหมือนเดิม จุดที่ยังไม่ได้ยืนยันคือตัวผูกปุ่มและฟอร์มของ BOM (`bindRoot` ใน `modules/module-bom.js`) ยังไม่ถูกเปิดให้โมดูลอื่นเรียก

## โมดูลทั้งหมดและฟังก์ชัน

สัญลักษณ์: **ย้าย** = มีแล้ว ย้ายมาจากที่ระบุ · **ใหม่** = ยังไม่มี ต้องสร้าง · **รอตัดสิน** = ต้องให้เจ้าของกำหนดกติกาก่อน

ทุกโมดูลมีหน้าแรกเป็น "งานของแผนกฉัน" (สิ่งที่ต้องทำตอนนี้ของแผนกนั้น) และแสดงเฉพาะของแผนกตัวเอง

### 01 ฝ่ายขาย (SA) — `#/sa` · ใหม่ทั้งโมดูล

- ออกใบสั่งผลิต: ลูกค้า สินค้า จำนวน กำหนดส่ง แล้ว "ส่งให้ฝ่ายวางแผน" (**ใหม่** · วันนี้ฝ่ายวางแผนเปิดใบเอง)
- ทะเบียนลูกค้า (**ย้าย** จาก BOM หน้าลูกค้า)
- ติดตามสถานะใบของตัวเองถึงขั้นส่งมอบ ดูอย่างเดียว (**ใหม่**)
- **รอตัดสิน**: ฝ่ายขายแก้หรือยกเลิกใบหลังส่งให้ฝ่ายวางแผนได้ถึงขั้นไหน

### 02 ฝ่ายวางแผน (PP) — `#/pp` · คือโมดูล BOM เดิม เปลี่ยนชื่อและตัดงานแผนกอื่นออก

- สินค้าและ BOM: ค้นหา ต้นไม้โครงสร้าง แก้ทีละบรรทัด วางจาก Excel คัดลอกโครงสร้าง ขั้นตอนผลิต ชุดสี แพ็กเกจ นำเข้า Excel ตรวจข้อมูล (มีแล้ว)
- ใบสั่งผลิต: รับใบจากฝ่ายขาย คำนวณวัตถุดิบ ตรวจของ (ของซื้อ เคมี สต็อกสินค้าสำเร็จรูป ยางเส้นยาวในคลัง SR) ปล่อยผลิต ติดตามทุกแผนก ปิดงานพร้อมเหตุผล ยกเลิกใบ (มีแล้ว)
- ใบพิมพ์รายแผนกและ CSV (มีแล้ว)
- บันทึกการใช้งาน (มีแล้ว)
- ออกจากโมดูลนี้: คลังของซื้อ → ST · คลังยางเส้นยาว → SR · รับเข้าและส่งมอบสินค้า → WH · การ์ดงานของแผนกผลิต → โมดูลของแต่ละแผนก

### 03 คลังวัตถุดิบ (ST) — `#/st`

- **ในคลังมีอะไร**: ของซื้อ (ยอดคงเหลือ สต็อกขั้นต่ำ ประวัติ) และเคมี (ล็อต วันหมดอายุ กักหรือปล่อย) ในหน้าเดียว ค้นหาได้ (**ย้าย** ของซื้อจาก BOM หน้าคลังของซื้อ · เคมีจาก RubberFlow หน้าคลังวัตถุดิบ)
- สั่งซื้อส่วนที่ขาด รับเข้าทีละส่วน ปิดยอดที่เหลือ ยกเลิกใบสั่งซื้อ (**ย้าย** จาก RubberFlow)
- เบิกจ่ายของซื้อตามใบ คืนของเหลือ ยกเลิกการเบิก (**ย้าย** จาก BOM)
- จ่ายเคมีตามใบเบิกของ RB และรับเคมีคืน (**ย้าย** จาก RubberFlow)
- นับสต็อก (**ย้าย** จาก BOM)
- ป้ายติดของ (**ย้าย** จาก RubberFlow)

### 04 ขึ้นรูปยาง (RB) — `#/rubberflow` · RubberFlow เหลือเฉพาะงานของ RB

- คงไว้: ใบสั่งผลิตยาง สูตรยางและการอนุมัติสูตร ใบเบิกเคมี ผสม ฉีดขึ้นรูป อบ ตกแต่ง ส่งมอบ WIP แม่พิมพ์และหัวดาย ภาพรวมของ RB
- ออกจากโมดูลนี้: คลังวัตถุดิบและใบสั่งซื้อ → ST · รับมอบ WIP → SR · QC NCR CoA SPC สืบย้อนกลับ → QA · สินค้าสำเร็จรูปและส่งกล่อง → WH · เปิดและปล่อยใบสั่งผลิตยาง → ทำจากโมดูลฝ่ายวางแผน
- **ค้างไว้ตามคำสั่ง**: รวมขั้นผสม 1–3 และอบ Oven (ลำดับ 04 ขั้น 8, 9, 11)

### 05 คลังยางเส้นยาว (SR) — `#/sr` · ทำใหม่จากฐานของ #389

- **ในคลังมีอะไร** (หน้าแรก): รายการยางเส้นยาวที่อยู่ในคลังตอนนี้ ต่อรายการเห็นรหัส ชื่อ สูตรยาง สี ขนาด จำนวนเส้น ล็อต วันที่รับ และของใบไหนหรือเป็นสต็อกกลาง ค้นหาและกรองได้ (**ใหม่** · ข้อมูลสูตร สี ขนาด มีในทะเบียนชิ้นงานและในล็อตแล้ว แต่หน้าเดิมไม่แสดง)
- รับยางเข้าคลังจาก RB พร้อมบันทึกขนาด (**ย้าย** จาก BOM)
- จ่ายยางให้ GR ตามใบ และประวัติเข้าออกต่อล็อต (**ย้าย** จาก BOM)
- รับมอบ WIP ระหว่างสถานีของ RB (**ย้าย** จาก RubberFlow)
- ปรับยอดจากการนับจริง (**ย้าย** จาก BOM · วันนี้เป็นสิทธิ์ฝ่ายวางแผน **รอตัดสิน**ว่าให้ SR ทำเองหรือไม่)
- รับยางที่ไม่ได้มาจากใบสั่งผลิต เช่น ยางค้างสต็อกเดิม ยอดยกมา (**ใหม่** · **รอตัดสิน**)
- ตำแหน่งจัดเก็บ (ชั้น โซน) (**ใหม่** · **รอตัดสิน**)
- ป้ายติดมัดยาง (**ใหม่** · **รอตัดสิน**ว่าบนป้ายมีอะไร)
- แก้คำทั้งหมดเป็น "ยางเส้นยาว" และ "คลังยางเส้นยาว"

### 06 ตรวจคุณภาพ (QC/QA) — `#/qa`

- งานรอตัดสิน: ยางเส้นยาวที่ถูกกักตอนรับเข้าคลัง ล็อตที่ถูกกักในสายการผลิต (**ย้าย** จาก BOM และ RubberFlow)
- บันทึกผลตรวจ NCR CoA SPC สืบย้อนกลับ กักและปล่อยวัตถุดิบ ข้ามเวลาบ่ม (**ย้าย** จาก RubberFlow)
- ลิงก์ไปใบตรวจ QC และ NCR/CAR ที่เป็นโมดูลแยกอยู่แล้ว
- **รอตัดสิน**: ผังเขียนว่า QC ตรวจขนาดขณะรับเข้าคลัง วันนี้ SR เป็นคนวัดและ QA ตัดสินเฉพาะที่ไม่ผ่าน ให้คงแบบนี้หรือให้ QA เป็นคนวัด

### 07 แปรรูปยาง (GR) — `#/gr` · ใหม่ทั้งโมดูล (เจ้าของสั่งให้ทำต่อจาก SR)

- งานของแผนก GR ตามใบ (**ย้าย** การ์ดงานและรายงานผลจาก BOM)
- เบิกยางเส้นยาวจากคลัง SR และเห็นว่าได้ยางล็อตไหน (**ย้าย** ส่วนแสดงผล · **ใหม่** ส่วนขอเบิก)
- บันทึกทีละขั้น ตัด → ทากาว → เจียรแปรรูป → คัดแยก ยอดดีและเสียต่อขั้น (**ใหม่** · มี repo Grinding-GR ของเจ้าของเป็นต้นแบบ)
- ส่งต่อให้ PK (**ใหม่**)
- **รอตัดสิน**: ระดับการบันทึก (ต่อขั้น หรือยอดรวมต่องาน) และชิ้นยางที่ทำเสร็จเก็บที่ไหนก่อนถึง PK

### 08 ขึ้นรูปพลาสติก (PT) — `#/pt` · ใหม่ทั้งโมดูล

- งานของแผนก PT ตามใบ รายงานยอดดีและเสีย พักงาน (**ย้าย** จาก BOM)
- วัตถุดิบที่ได้รับจาก ST สำหรับงานนั้น (**ใหม่** ส่วนแสดงผล)
- ส่งต่อให้ PK (**ใหม่**)

### 09 เย็บจักร (BG) — `#/bg` · ใหม่ทั้งโมดูล

- งานของแผนก BG ตามใบ รายงานยอดดีและเสีย พักงาน (**ย้าย** จาก BOM)
- วัตถุดิบที่ได้รับจาก ST สำหรับงานนั้น (**ใหม่** ส่วนแสดงผล)
- ส่งต่อให้ PK (**ใหม่**)

### 10 ประกอบและบรรจุ (PK) — `#/pk` · ใหม่ทั้งโมดูล

- งานของแผนก PK ตามใบ รายงานผล พักงาน (**ย้าย** จาก BOM)
- ของที่รอรับจาก GR, PT, BG ของแต่ละใบ และพร้อมประกอบหรือยัง (**ใหม่**)
- 3 ขั้น ประกอบ → ใส่กระเป๋า → บรรจุกล่อง (**ใหม่** · **รอตัดสิน**ว่าติดตามรายขั้นหรือยอดรวม)
- ส่งสินค้าให้ WH (**ย้าย** · วันนี้ WH เห็นยอดที่ PK รายงาน)

### 11 คลังสินค้าสำเร็จรูป (WH) — `#/wh`

- **ในคลังมีอะไร** (หน้าแรก): สินค้าสำเร็จรูปคงเหลือต่อรหัส ของใบไหนหรือเป็นสต็อกกลาง ค้นหาได้ (**ใหม่** ส่วนแสดงผล · ข้อมูลมีแล้ว)
- รับสินค้าจาก PK ทีละส่วน ปิดใบ ปิดใบรับไม่ครบ (**ย้าย** จาก BOM ขั้น 5)
- ส่งมอบลูกค้า และแก้รายการที่กรอกผิดโดยหัวหน้าคลังสินค้า (**ย้าย** จาก BOM ขั้น 6)
- กล่องสินค้าและการส่งกล่องของ RubberFlow (**ย้าย** จาก RubberFlow)

### โครงร่วม (ไม่ใช่โมดูลของแผนก)

- เมนูหลักมีกลุ่ม "โรงงาน" เรียงตามลำดับผังงาน 01–11 พนักงานเห็นเฉพาะโมดูลของแผนกตัวเอง ฝ่ายวางแผนและผู้จัดการเห็นทุกโมดูล (**รอตัดสิน**เรื่องสิทธิ์ของหัวหน้าแผนก ที่วันนี้เท่ากับฝ่ายวางแผน)
- ชิ้นส่วนที่ใช้ร่วมกัน: ตัวผูกปุ่มและฟอร์ม การ์ดงาน หน้าต่างรายงานผล ป้ายแผนก แยกออกเป็นไฟล์กลางให้ทุกโมดูลเรียก
- ข้อมูลและฐานข้อมูลใช้ของเดิม การย้ายหน้าจอไม่ต้องย้ายข้อมูล งานที่เป็น **ใหม่** บางข้อเท่านั้นที่ต้องมี migration

### คำถามของขั้น 1 (โมดูล SR)

1. ยางในคลังชี้บ่งด้วยอะไรที่หน้างาน เช่น รหัสเส้นยาง สูตร สี ขนาด วันที่ผลิต เลขล็อต หรือป้ายที่ติดกับมัด
2. คลังมีชั้นหรือโซนที่ต้องบันทึกหรือไม่
3. ยางที่ไม่ได้มาจากใบสั่งผลิต (ค้างสต็อกเดิม ผลิตเผื่อ) ต้องรับเข้าคลังได้หรือไม่ และใครเป็นคนบันทึก
4. SR ปรับยอดจากการนับจริงเองได้ หรือต้องให้ฝ่ายวางแผนทำ

## กติกาการทำงานของ session

ปัญหาที่เกิด: session เดียวทำหลาย PR ต่อกันจน context เกินครึ่ง แล้วเริ่มตอบจากความจำที่ผิด และคำสั่งหลักของเจ้าของหลุดระหว่างส่งต่องาน

1. **หนึ่ง session ทำหนึ่ง PR แล้วจบ** เขียนบันทึกส่งต่อ อัปเดตบันทึกของโปรเจกต์ แล้วหยุด ห้ามเริ่มงานชุดถัดไปเอง และห้ามรับงานต่อเนื่องใน session เดิม งานถัดไปเริ่มใน session ใหม่เสมอ
2. **คำสั่งงานของแต่ละ session ครบในตัว**: ไฟล์กติกาที่ต้องอ่าน แผนฉบับนี้ บันทึกส่งต่อของ PR ก่อนหน้า ขอบเขตที่ทำ และสิ่งที่ห้ามทำ บรรทัดแรกของคำสั่งงานระบุว่างานนี้เป็นของโมดูลแผนกไหน
3. **ใน session ให้ผู้ช่วยทำงานหนัก**: อ่านและไล่โค้ดให้ `researcher` แก้โค้ดให้ `coder` ตรวจให้ `auditor` ตัว session หลักเก็บเฉพาะข้อสรุป ไม่ดึงไฟล์ใหญ่หรือผลลัพธ์ยาวเข้ามา
4. **session สั่งงานทำหน้าที่ส่งต่อเท่านั้น**: เปิด session รายงานผลสั้นๆ ไม่อ่านบทสนทนาทั้งหมดของ session ย่อย เมื่อบทสนทนาของตัวเองยาว (หลายวัน หรือถูกย่อความไปแล้ว) ให้แจ้งเจ้าของและเริ่ม session สั่งงานใหม่จากแผนฉบับนี้
5. **พูดเฉพาะสิ่งที่ตรวจแล้วใน session นั้น** จากโค้ดบน `origin/main` จาก GitHub หรือจากไฟล์ที่เพิ่งอ่าน สิ่งที่มาจากบันทึกให้บอกว่า "จากบันทึก ยังไม่ได้ตรวจซ้ำ"
6. **ถามกติกาธุรกิจก่อนสร้าง ไม่เดา** และก่อนส่งให้ลอง ต้องเทียบงานกับหลัก 5 ข้อบนสุดของแผนนี้ทีละข้อ
7. คงกติกาเดิม: ลองบน localhost ก่อนเสมอพร้อมสรุปสิ่งที่ปรับปรุง · push เปิด PR merge และใช้ migration กับฐานข้อมูลจริง ต้องให้เจ้าของสั่งใน session นั้น · วิธีใช้ agent ตาม `CLAUDE.md` และ `docs/BOM_NEXT_PLAN.md`
