## Job
ผู้อนุมัติตัดสินจากคิว; หัวหน้าแผนก/ช่างเห็นงานซ่อมที่ต้องลงมือ (pending_assign/assigned/in_progress/pending_verify จาก getMyRepairActionItems); ผู้แจ้งเห็นใบของฉันที่ยังไม่จบ + แจ้งใหม่; ทุกคนสร้างคำร้องได้

## Direction contract
THESIS: หน้าหลักมีงานเดียวคือ "สิ่งที่รอคุณ" และตัดสินได้ตรงนั้น ปฏิเสธโครง "tile ตัวเลข + feed + ทางลัด" ที่โชว์ใบเดียวกันสามครั้ง
OWN-WORLD: token เดิม; การ์ดคิวใช้ชิปเลขที่ mono + ไอคอนประเภท + จุดด่วน; ไม่มี gradient
STORY: เปิดมาเห็นจำนวนงานค้าง → แตะใบแรก ขยายในที่ → ตัดสิน → ยุบเป็นบรรทัด "อนุมัติแล้ว · เวลา" → ใบถัดไปขยายเอง → คิวว่าง "ไม่มีงานค้าง"
FIRST VIEWPORT (375px): หัว "งานของคุณวันนี้" + วันที่ + ปุ่มสร้างคำร้อง 48px (ผู้ไม่มีสิทธิ์อนุมัติ: ปุ่มกว้างเต็มแถวใต้หัว) / "ต้องจัดการ (n)" การ์ดเรียงด่วนก่อน เก่าสุดก่อน: เลขที่ · ประเภท(ไอคอน) · ชื่อเรื่อง · ผู้แจ้ง · ค้าง n วัน / แตะ = ขยายในที่ (รายละเอียด 3 บรรทัด + รูปแรก + 3 ปุ่ม 44px + ช่องเหตุผลเมื่อต้องใช้ + ลิงก์ "เปิดเต็ม") / การ์ดงานซ่อม = ป้ายสิ่งที่ต้องทำ แตะไปรายละเอียด / checkbox 24px มุมการ์ด → แถบติดล่าง "อนุมัติที่เลือก (n)" / ต่อด้วย "ใบของฉันที่ยังไม่จบ (n)" บรรทัดละใบ + แถบความคืบหน้า. Desktop ≥1024: master-detail รายการซ้าย 1/3, ใบที่เลือกขวา 2/3 (การ์ด+กล่องตัดสินใจแบบหน้ารายละเอียด); คีย์ J/K/A/R (A,R ผ่านกล่องยืนยัน) และ / ; คำใบ้คีย์ลัดจาง ๆ ใต้รายการ
